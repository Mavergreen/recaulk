A program for Mac OS X 10.9 that calls C11's `aligned_alloc` now builds with Recaulk alone:
`<stdlib.h>` declares it, in C and C++, wherever the SDK does not. Recaulk already supplied the
function. Before, a project such as clang's libc++ needed its own copy.

On 10.9 the pthread QoS calls now answer as Apple's own libpthread does on a system without QoS:
`pthread_set_qos_class_self_np` and the other setters and getters return `ENOTSUP`,
`qos_class_self()` and `qos_class_main()` return `QOS_CLASS_UNSPECIFIED`, and
`pthread_override_qos_class_start_np` returns `NULL`. They used to report success and
`QOS_CLASS_DEFAULT`. Newer macOS still answers with the system's own.

MacPorts' headers now ship byte for byte as MacPorts wrote them. Where Recaulk adds to one
(`stdlib.h`, `dirent.h`, `netdb.h`), MacPorts' copy is under `_recaulk_macports/` and Recaulk's
header includes it first. Nothing changes for a program that includes them as before.
