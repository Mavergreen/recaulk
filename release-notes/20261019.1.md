C++ built for Mac OS X 10.9 against the system's own `libc++abi` now links with Recaulk alone. Recaulk
fills in what 10.9's `libc++abi` lacks and a modern libc++ or clang calls:
`std::uncaught_exceptions()`, `std::make_exception_ptr`, the terminate step at the end of a `noexcept`
function, the too-small array bound in a `new` expression, and `typeid` and catching for `char8_t`,
`_Float16`, `__float128`, `__int128` and pointers to them. Newer macOS still answers with the system's
own functions where it has them.

This is what lets a program use one C++ runtime alongside Cocoa. Before, a toolchain had to carry its own
`libc++abi`, and a C++ exception crossing between it and the system's (around a Cocoa call that raises,
for instance) crashed the program.

Pass `-lc++abi` when linking C++ that uses these.
