A program for Mac OS X 10.9 can now sign with `SecKeyCreateSignature` as it would on 10.12 and
later. It takes Apple's `SecKeyAlgorithm` constants and makes RSA PKCS#1 v1.5 and ECDSA signatures
over SHA-1, SHA-224, SHA-256, SHA-384 and SHA-512 digests. Before, it took the wrong kind of argument
and returned nothing. RSA-PSS, which 10.9 cannot make, fails with an error saying the key does not
support the algorithm, as it does on any macOS for an algorithm a key cannot do. Recaulk adds the
ECDSA SHA-1 to SHA-512 and RSA SHA-224 algorithm constants.

When `SecTrustEvaluateWithError` does not trust a certificate, its error now says why the way later
macOS does, with a code such as `errSecNotTrusted` or `errSecCertificateExpired`. It used to carry
code 0.

`<Security/Security.h>` from Recaulk's headers declares these where the 10.9 SDK does not. Newer
macOS still uses its own.
