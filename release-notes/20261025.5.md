On Mac OS X 10.9, `objc_readClassPair` no longer crashes when it realizes a subclass of `NSObject`, or
of any class with categories. Swift's runtime realizes classes through it, a generic class among them.
It copied the wrong flag from the superclass: a bit that tells 10.9's runtime the class holds several
method lists. The next method lookup on the new class then crashed in `search_method_list`. A subclass
now copies only the custom retain/release and `allocWithZone:` flags, the two that 10.9's runtime
copies itself.

Objects of a class realized this way now run `.cxx_construct` and `.cxx_destruct`, the class's own and
its superclasses'. Swift initializes and destroys a class's stored properties there when the class has
Objective-C ancestry, so before this they leaked when the object was freed. A class whose superclass
had not been used yet now also inherits the superclass's retain/release and C++ behaviour.

Newer macOS has its own `objc_readClassPair`, and Recaulk's still defers to it there.
